# Gridify tutorials

Small applications that use the Gridify library (`@gridify/studio`), from the very basics on. They are projects of the Angular workspace of the repository: one `npm i` in the root installs what all of them need, and a tutorial is started by its number, in the root:

```
npm i
npm run tutorial 010
```

`npm run tutorial 010` serves the tutorial `010-hello-world` and opens http://localhost:30010 in the browser. `npm run tutorials` lists them all, with their addresses.

## What you need

- **Node.js** in a version that Angular 21 supports (20.19 or newer, 22.12 or newer, or 24) and the npm that comes with it.
- **One `npm i` in the root of the repository.** The tutorials have no `package.json` and no `node_modules` of their own; the Angular CLI is the one of the workspace, so it does not have to be installed globally.

## Running a tutorial

```
npm run tutorial 130
```

The tutorial can be named by its number (`130`), its folder (`130-languages`) or its project (`tutorial-130`); the start of a number or a name is enough when only one tutorial has it (`npm run tutorial 13` lists the six that do). The command runs `ng serve tutorial-130 --open`. Options after `--` go to `ng serve` as they are: `npm run tutorial 130 -- --port 4300`.

`ng serve tutorial-130` does the same when the Angular CLI is installed globally, and `ng build tutorial-130` builds the tutorial into `dist/tutorials/130-languages`.

### Ports

Every tutorial has a port of its own: 30000 plus its number. 010 runs on http://localhost:30010, 130 on http://localhost:30130. So several tutorials can run at the same time, and each has a `localStorage` of its own, because `localStorage` belongs to the address (the scheme, the host and the port). The tutorials still keep what they save under keys of their own (`tutorial-130-layout`), as an application should: everything that runs on one address shares one `localStorage`.

### A tutorial as a project of its own

A tutorial folder holds only `src/`, `public/`, `README.md` and `tsconfig.app.json`; the rest is in the workspace (`angular.json` of the root, `tutorials/tsconfig.json`). To take one out as a complete Angular project, the one `ng new` makes, see [Make a tutorial a project of its own](#make-a-tutorial-a-project-of-its-own).

## Make a tutorial a project of its own

```
npm run tutorial:eject 130 ../languages
```

writes the tutorial `130-languages` into the folder `../languages` (taken from where the command is typed; it must be new or empty) as a complete Angular project: `package.json`, `angular.json` with one project on http://localhost:4200, `tsconfig.json`, `tsconfig.app.json`, `.gitignore`, `.editorconfig`, `.npmrc`, `.prettierrc.json`, and the `src/`, `public/` and `README.md` of the tutorial. Then:

```
cd ../languages
npm i
ng serve
```

(`npm start` does the same as `ng serve` without the Angular CLI installed globally.)

The project takes the library as `@gridify/studio` from npm, in the version of the library. While Gridify is not on npm, give it the package built in the repository:

```
npm run build:studio:community
npm run tutorial:eject 130 ../languages -- --library dist/studio-community
```

`--library` takes a version (`--library ^1.2.0`), a package folder or a `.tgz` file. A folder is packed by npm into a `.tgz` file in the new project, and a `.tgz` file is copied there, so the project installs the library from its own folder (`"@gridify/studio": "file:./gridify-studio-0.0.0.tgz"`), the way npm installs a package from the registry.

## The library

In this repository the tutorials take the library from its source, `src/app/components`, not from a package: `tutorials/tsconfig.json` leads `@gridify/studio` there (`paths`), and the load path `tutorials/.dev` leads `@use '@gridify/studio/styles'` to the styles of the source. A change of the library is in the running tutorial at once, with no package to build.

The code of a tutorial is the code of an application that installed the package: it imports from `@gridify/studio` and nothing else. Before a release, `npm run tutorials:check` proves it: it builds the community package, puts it into `tutorials/node_modules` the way npm would install it, builds every tutorial from the package (the configuration `package` of its project), reports what failed, and removes `tutorials/node_modules` again.

The tutorials have no license key, so the console of the browser says once, a moment after the page has loaded, that this is the Community edition: it is free for non-commercial projects, education and personal hobby development. A commercial application gives the key of its license with `provideGridifyLicense('…')` in `app.config.ts` (the README of the package, _License_).

The samples (`npm run export:samples`, `dist/gridify-samples.zip`; internal only, because they carry the source of the playground) have the tutorials and the playground in a workspace of their own that takes `@gridify/studio` from npm. `npm run export:tutorials` (`dist/gridify-tutorials.zip`) makes the same without the playground: a project for a repository of the tutorials, whose `npm run build` builds every tutorial (a workflow of GitHub Actions does it on every push). Here `npm run tutorials:build` builds them all from the source of the library. `npm run export:playgrounds` (`dist/gridify-playground.zip`) is the playground alone, internal only for the same reason.

## The style of the tutorials

The tutorials are written the way a new Angular project is (2 spaces, single quotes, lines up to 100 characters), not in the style of the library (4 spaces). `tutorials/.editorconfig` and `tutorials/.prettierrc.json` hold it, so an editor and Prettier use it for every file under `tutorials/`:

```
npx prettier --write tutorials/130-languages
```

## Adding a tutorial

A new folder `tutorials/NNN-name` with `src/main.ts`, `src/index.html`, `src/styles.scss`, `public/` and a `README.md`, and a row in a table above (the first sentence of the row is what `npm run tutorials` shows). Then

```
npm run tutorials:sync
```

adds its project `tutorial-NNN` to `angular.json` (port 30000 + NNN) and writes its `tsconfig.app.json`. It also puts right a project that differs from what its folder needs and removes the project of a folder that is gone; `npm run tutorials:sync -- --check` only tells whether something would change.
